# Второй спринт AI Core

Базовая ревизия второго спринта — 657a636. Работа ведётся в feature/ai-core.

## Ревью и цикл инструментов

- Изучены пути запуска из app.py, сборщики аналитики, transport Qwen, нормализация источников, журнал, SQLite, фоновый мониторинг, интерфейс и существующие проверки. Исходный набор прошёл 25 из 25 тестов.
- До изменения выбор шага Qwen только менял порядок готового контекста. Теперь каждый ответ планировщика выбирает один инструмент из оставшихся. Следующий ответ получает найденные доказательства и статусы вызовов. Аргументы берутся из согласованного запроса оператора. Неизвестный инструмент, повтор и неожиданные аргументы отклоняются. При отказе модели локальные инструменты сохраняют рабочий режим.
- Продажи, воронка, Метрика, релизы, исследования, локальные и публичные конкуренты, бэклог разнесены по инструментам. Журнал показывает фактические вызовы, ошибки и выбранные источники. Явно непрофильный запрос завершает исследование до чтения источников.
- При сокращении контекста модель сначала получает по представителю нескольких видов доказательств. Ограничиваются отрывки и бюджет запроса. Сервер сохраняет исходные значения и идентификаторы.
- Выполнены 29 Python-тестов и локальный Chrome QA. HTTP-тест проверяет две последовательные операции с наблюдением между ними и восстановление после некорректного JSON синтеза. Тесты отдельно подтверждают запрет повторного запроса и прямой передачи URL из ответа модели.

## Открытые задачи и внешние зависимости

- Следующий этап связывает пороговую проверку с расследованием и устойчивым уведомлением. В исходной реализации мониторинг создавал только запись пересечения порога.
- Требуются содержательная рубрика, перекрёстный анализ разнородных источников, проверка эффекта и усиление принятия решения о дублях. В исходной реализации наличие ссылки на evidence подтверждало формат, но не смысл вывода.
- На момент начала PM_LLM_URL, пути материалов Softline и учётные данные Метрики не заданы. Имеется проверенный локальный Qwen3-0.6B для живой синтетической проверки. Его результаты будут указаны отдельно от Qwen3-4B. Внешний поисковый провайдер по-прежнему принадлежит второй ветке.


## Перекрёстный анализ и фоновое расследование

- Сервер вычисляет разницу изменений основной и контрольной групп. Для Метрики проверяются совпадающие календарные окна, тип счётчика, сегмент и качество. Синтетический счётчик не используется как подтверждение фактической динамики заказов.
- Отдельно отмечаются соседние релизы, тематические связи интервью, конкурентных материалов и бэклога, а также устаревшие сведения. Связи между выдержками маркируются предположениями. Уровень уверенности не растёт при повторном цитировании одного файла.
- Фоновый мониторинг проверяет полноту окна, ставит новое расследование в транзакционную очередь и создаёт связанное уведомление. Дневной лимит и аренда предотвращают повторный запуск в нескольких процессах. Согласование задач остаётся ручным.
- Первый живой прогон Qwen3-0.6B выявил несовместимые комбинации инструмента и цели в JSON и преждевременное завершение. Контракт решения внутри Qwen сведен к одному перечислению. Запрошенные локальные проверки завершаются перед принятием решения. Непродуктовый запрос не получает найденные данные.
- Синтетические тесты проверяют противоположную динамику заказов и визитов, отсутствие контроля, устаревший конкурентный источник, недоступность Метрики, дедупликацию уведомлений и дневной лимит.


## Критерии, документы и содержательные проверки

- Базовый четырёхнедельный индекс рассчитывается из тех же недельных значений, что и после релиза. Предложение связывает гипотезу с критериями и существующими задачами. Для близкой задачи предлагается пересмотр приоритета. Оценка хранит внешние факторы, контрольное изменение и согласованный порог отказа.
- Предварительный просмотр TXT, DOCX, PPTX, PDF и выбранных диапазонов Excel работает без записи. Новые фрагменты хранятся транзакционно в SQLite. Старый локальный индекс читается для совместимости. Эталонный лист исключается из импорта и переданного JSON по происхождению.
- Добавлены повторное расследование с изменением источников, сводка рабочего и синтетического режимов отдельно, тесты параллельных импортов и повторного согласования.
- Автоматическая рубрика проверила четыре независимых синтетических сценария без модели. Первая живая серия Qwen3-0.6B подтвердила самостоятельный выбор нескольких инструментов и обработку неполных данных, но не прошла критерий валидной гипотезы для сигнала падения из-за таймаута синтеза. После разделения компактного ответа модели и вычисляемых полей сервера сценарий падения прошёл живую рубрику за 49,928 с и 6859 токенов. На момент фиксации этапа пройдено 48 Python-тестов и Chrome QA. Проверки стабильности и пропусков с локальной Qwen заняли соответственно 6,124 и 4,232 с без ненужного синтеза гипотез. Через HTTP сохранены 24 независимых отчёта в одной SQLite при шести параллельных клиентах. В отдельном тесте сервер сохранил фоновый отчёт и уведомление за 61,17 с при настроенном интервале 60 с.


## Release Candidate и продуктовая память

База этапа — 1273e73. Исходный набор второго спринта прошёл 48 тестов. Выявлены три пробела для эксплуатации: текущие ряды исчезали при смене источника, версии импортированных документов перезаписывались, а резервное восстановление не было проверено.

Добавлены отдельные таблицы наблюдений, источников, рядов, версий документов, связей с расследованиями и журнала синхронизаций. Сравнения выполняются параметризованным SQL и Python. Версии не переписываются, а повтор получения обновляет время проверки. Добавлены точные исторические инструменты, независимый снимок SQLite и проверка восстановления на синтетических данных. Для интерфейса, системных прав и приёмки предусмотрен следующий этап.

Живые Qwen3-4B, Метрика и рабочие данные Softline требуют настройки разрешённых ресурсов. Данные .vscode существовали в рабочей папке до начала этапа.
