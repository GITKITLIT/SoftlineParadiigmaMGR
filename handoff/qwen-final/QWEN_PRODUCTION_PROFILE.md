# Qwen · профиль для выпуска

Рекомендуемый профиль для отдельной ВМ 1Gb.ru — Qwen3-4B Q4_K_M и llama.cpp b12800 с Sandy Bridge CPU backend. Один слот, контекст 8192, 4 потока генерации и 4 потока батча, F16 KV, кеш 512 МиБ и reasoning off. Backend находится отдельно и обращается к модели через существующий защищённый SSH-forward на loopback. [Результаты 1Gb.ru](QWEN_LINUX_ACCEPTANCE.md) · [Настройка runtime](QWEN_FINAL_RUNTIME.md)

| Стадия | Секунды |
| --- | ---: |
| HTTP планировщика | 120 на попытку |
| Планирование от начала исполнения | 410 |
| HTTP синтеза | 240 на попытку |
| Синтез | 270 |
| Общий бюджет модельных HTTP-вызовов | 700 с допуска |
| Ожидание единственного слота Core | 700 |
| Опрос статуса клиентом | 1500 |

Core допускает одно выполняемое расследование и одно в ожидании. Третье получает сообщение о занятой очереди. Сервер сохраняет отчёт после успешного завершения. Предел 1500 с покрывает два модельных бюджета с резервом 100 с. Тайм-ауты внешних инструментов задаются отдельно, поэтому клиент при исчерпании времени может открыть сохранённый результат позже. Очередь действует в одном процессе Backend. Пределы ручных синхронных запросов и Nginx разделены с асинхронным опросом статуса. Длинные расследования запускайте через штатные маршруты `start/status`.

## Применение владельцем Deployment

1. Используйте коммиты реализации из `handoff/qwen-final` поверх принятого RC. Штатный `scripts/run_model.py` принимает `--threads-batch 4`. Сравните эффективный запуск с [профилем службы](runtime/30-qwen-batch4-launcher.conf) и сверьте вес, бинарник и AppArmor по [инструкции runtime](QWEN_FINAL_RUNTIME.md).
2. Включите в Backend `PM_QWEN_RUNTIME_PROFILE=sandy-bridge-one-slot` и `PM_QWEN_STABLE_PLANNER_PREFIX=true`. Сохраните текущие loopback URL и алиас модели. Опубликованные исторические патчи уже включены в коммиты этой ветки.
3. Пересоберите конфигурацию Nginx штатным рендерером после изменения JavaScript, чтобы обновился CSP-хеш. Проверьте `nginx -t`, вход и разделение историй. Для асинхронных маршрутов оставьте действующий `proxy_read_timeout`. Сверьте SHA Backend и профиль до открытия входа.
4. Для отката выключите две переменные профиля и верните прежние совместимые сборку, конфигурацию Nginx и runtime, если они изменялись. Применяйте откат в согласованное окно. Сверьте `health`, доступ к сохранённой истории и резервный ответ Core. Для короткого живого показа проверьте фактическое время заранее. Linux-история заняла около 54 с в последней подтверждённой серии.
