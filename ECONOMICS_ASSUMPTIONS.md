# Экономика ParadiigmaMGR · черновик

Официальный файл готовится на исходном листе «Расчёт». Жёлтые ячейки — входные данные. Серый пример исключён из суммы `I13`. Формулы `I9:I12` считают модельную часть, а затраты на серверы, поиск и допущения указываются в комментарии. Курс USD в `I3` не нужен для заполненной рублёвой строки. Черновик передаётся отдельно от Git.

## Стоимость запроса и месяца

- Прямые расходы вопроса без Search — 0 ₽ за модельные токены и Search. Полная цена вопроса включает его долю инфраструктуры и прочих переменных расходов.
- Прямые расходы расследования — `0,40 × дневные вызовы + 0,30 × ночные вызовы` в рублях без НДС. Пример с одним дневным Search — 0,40 ₽, с подтверждённым попаданием в кеш — 0 ₽ за API. Для отдельной себестоимости расследования прибавьте распределённую долю сервера.
- При постоянной работе `полный месяц = фиксированная аренда и сопутствующие услуги + Search + прочие переменные расходы`. Если Backend и модель на одном VPS, учтите его аренду один раз. Переменные расходы могут включать SMTP, трафик сверх пакета и операции хранения. Средний полный запрос: `полный месяц / (пользовательские операции + расследования мониторинга)`. Модельная нагрузка не добавляется второй строкой к уже оплаченной аренде.
- Для разделения инфраструктуры по типам запроса можно распределить затраты модели на пропорциональную долю измеренного времени слота, а общий Backend и хранение — по числу операций. При `T = Σ(nᵢ × tᵢ)` один запрос класса i получает `F_model × tᵢ / T + F_common / Σnᵢ` плюс его прямые расходы. Для разделения общего VPS нужна задокументированная база распределения. При отсутствии замеров целевой сборки публикуйте только среднее и прямые расходы.
- Для запуска по запросу: `постоянный Backend + диски и прочие постоянные услуги + тариф машины × биллинговые часы модели + Search`. Учитывайте округление биллинга, холодный запуск и время простоя до остановки. Режим и экономия не подтверждены. Сон процесса на арендованном сервере не сокращает оплаченные часы.
- Стенд конкурса: учитывайте период бронирования и фактическую схему оплаты. Подставьте `цена аренды за срок + диски/копии/сеть за срок + оплаченные вызовы`. Если Search отключён, его расход равен нулю после проверки конфигурации выставленного стенда.

| Менеджеров | Операций в месяц, сценарий | Часы Qwen в месяц, эквивалент по Mac | Search, обычный режим с кешем до лимита | Search ₽ днём без НДС | Полный месяц / на менеджера |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 177,67 | 0,565 | 104 | 41,60 | `(F₁ + V₁ + 41,60) / 1` |
| 5 | 767,00 | 2,090 | 280 | 112,00 | `(F₅ + V₅ + 112,00) / 5` |
| 35 | 5 187,00 | 13,524 | 1600 | 640,00 | `(F₃₅ + V₃₅ + 640,00) / 35` |

В последней колонке числитель — полная стоимость сценария, результат деления — на одного менеджера. `F` — фиксированные расходы с учётом подтверждённой конфигурации для соответствующего масштаба. `V` — прочие переменные расходы. При общем лимите 20 попыток в сутки расчёт Search handoff для 35 менеджеров оценивает 456 попыток, или до 182,40 ₽ днём в обычном сценарии. Лимит снижает покрытие. График нагрузки, время поиска и кеширование могут менять сумму. Месячные часы Qwen — пересчёт оценки по Mac, калибровка для целевого VPS и SLA требуются отдельно.

## Проверка предварительной сборки

У локального `ParadiigmaMGR_Official_Cost_Draft.xlsx` перепроверены исходные формулы, объединения, валидация и состав книги. Из контейнера шаблона изменён только XML листа «Расчёт». В `I13` сохранена модельная часть 0 ₽. Текущая строка по прежнему Mac-замеру агрегирована, поэтому перед публикацией файла нужно подтвердить сценарий записи и внести измеренные стадии.

- Search Live Final `574b391` подтвердил 0,49 ₽ потребления, такую же скидку и 0 ₽ к оплате за один пробный вызов. Для прогнозирования повторных запросов без скидки оставляем 0,40 ₽ днём и 0,30 ₽ ночью без НДС. Уточнить включение Search на стенде, распределение трафика, попадания в кеш и лимиты. [Фактическое начисление](SEARCH_LIVE_ACCEPTANCE.md#фактический-результат)
- В промежуточном Qwen handoff есть размеченный Mac-замер. Для `simple_chat` зафиксированы два вызова планирования на 979/16 токенов суммарно и два вызова синтеза на 1008/441. Для «Что проверить первым?» зафиксированы шесть вызовов планирования на 6309/48 и один вызов синтеза на 1041/296. Эти сценарии различаются. Выбирать строку по фактическому дублю и не суммировать агрегат с детализацией. Для показа нового запроса истории из сценария записи подтвердить использованные шаги в его фактическом профиле. [Промежуточный отчёт Qwen](https://github.com/GITKITLIT/SoftlineParadiigmaMGR/blob/3ba13eba2f78b12b51a044e3df54da87748629f5/handoff/qwen-final/QWEN_ECONOMICS_HANDOFF.md)
- **Максим** передаёт фактические стоимости Backend и модельного VPS, дисков, резервного хранения, сети, IP и SMTP, ставки НДС по компонентам, оплаченные сроки и условия отдельных тарифов. Для распределения стоимости нужны объём запросов и подтверждённая схема аренды или почасовой работы. **Амир** подтверждает соответствие сценария токен-замеру, Linux-профиль и измерения холодного и прогретого запуска, полной задержки и параллельной нагрузки. Затраты стенда и стоимость запроса остаются незаполненными до этих данных.

Владелец пилота измеряет ручное время и качество на сопоставимых кейсах. Сэкономленные часы и ROI не установлены.
