# Вопросы технического жюри

| Вопрос | Ответ |
| --- | --- |
| Почему Qwen3-4B Q4_K_M? | Локальные тесты подтвердили выбор инструментов и получение проверяемой гипотезы на небольшом runtime. GGUF занимает около 2,33 GiB. Windows CPU на синтетике дал 99,445 с для аномалии. Выбранный профиль нужно измерить на целевом Linux. |
| Почему локальный инференс? | Рабочий контекст не уходит в сторонний LLM API. Модель можно обновлять независимо от Backend. За токены нет тарифа поставщика, но сервер, диски и поддержка оплачиваются. |
| Откуда числа? | Python считает индекс, сравнение и показатели воронки по доступным данным. В отчёте указываются окно, контрольный ряд, знаменатель и качество наблюдения. В закрытой приёмке R-09 прошли 11 сверок с первичными таблицами. |
| Как вы проверяете выводы модели? | Core ограничивает инструменты, проверяет схему ответа и разрешимость ссылок. Правила приёмки требуют предположительную форму гипотезы и ссылку на основной ряд. Согласование остаётся за пользователем. Проверка ссылки сама по себе не устанавливает причинность. |
| Что при отказе модели или Search? | При отказе модели остаются расчёты и расследование по правилам. Поиск использует доступные локальные материалы и сохранённые снимки. Отчёт показывает статус источника и происхождение фрагмента. |
| Где лежат корпоративные данные? | Закрытые импорты и рабочая SQLite хранятся вне публичного Git. Защищённая конфигурация использует HTTPS, роли служб и отдельный vault. Аутентификация и разграничение проверены в одноразовом окружении. |
| Как устроена память? | PIM хранит версионированные наблюдения, доказательства и решения с происхождением. По двум сопоставимым окнам Python считает изменение. Синтетические и рабочие наблюдения помечены отдельно. Приватные диалоги привязаны к владельцу. |
| Где агентность? | На свежих данных монитор создаёт сигнал. Агент выбирает несколько разрешённых источников и собирает проверяемый отчёт. Ответ, черновик, план замера и история используют контекст расследования. |
| Как измеряете эффект? | Сохраняем цель, базу, контроль и способ проверки при согласовании. Оценка ждёт четыре полные недели. Сравнение показывает результат по заданному KPI, решение о закрытии остаётся у менеджера. |
| Что потребуется для 35 менеджеров? | Месячная нагрузка и пик одновременных запросов измеряются отдельно. Перед расширением проверим очередь, слоты на узел, p95 по классам запросов, RSS, квоты Search и восстановление. Дополнительный узел нужен, если один сервер не выдерживает измеренный пик. |
| Сколько стоит запрос и эксплуатация? | Локальные токены стоят 0 ₽ по тарифу модели. Один платный синхронный Search API днём стоит 0,40 ₽ без НДС. Для полной суммы нужны фактические счета целевого стенда и количество запросов. Формулы и сценарии для 1, 5 и 35 менеджеров приведены отдельно. |
| Почему важен выпуск на одном SHA? | Сводим к нему установку, запись, эксплуатационный расчёт и CI, чтобы жюри могло повторить заявленный сценарий. |
