Рабочая ветка — feature/ai-core, базовый коммит — 657a636. Первые этапы сохранены в b6b852b и dfc4050. Хронология ревью и проверок приведена в [PROGRESS.md](PROGRESS.md).

## Функциональность и архитектура

В цикле расследования Qwen видит список разрешённых инструментов и предыдущие наблюдения, выбирает один шаг и может завершить сбор. Сервер запускает выбранный инструмент с параметрами исходного запроса, исключает повторные шаги и сохраняет журнал фактических вызовов. Синтез получает данные и проверенные вычисления по разным источникам. Для каждого существенного вывода доступны ссылки, ограничения, пробелы и проверка. Недоступность модели оставляет локальный расчёт и гипотезы по правилам.

Python рассчитывает индексы и разницу изменений с контрольной группой. Визиты и заказы сопоставляются для совпадающих окон рабочего счётчика. Даже совпавшие даты не подтверждают общую товарную аудиторию или причинность. Интервью, конкурентные материалы, релизы и задачи связываются по релевантным фрагментам. Сниппеты, архивные материалы и повторные выдержки одного источника не повышают уверенность автоматически.

Фоновый серверный мониторинг проверяет окна и порог, записывает сигнал в SQLite и создаёт уведомление с готовым расследованием. Дедупликация действует и между процессами. Согласование фиксирует целевой показатель, базовое окно и дополнительные пороги. Похожие задачи переходят в предложение пересмотреть приоритет. Оценка эффекта учитывает контроль, внешние факторы и дополнительные показатели. Симуляции отделены от фактических записей.

В продукте доступны предварительный просмотр документов, журнал шагов, повторное расследование с перечнем изменений и раздельная дневная сводка. SQLite хранит новые фрагменты с атомарной заменой. Чтение прежнего sources.json сохранено.

## Содержательная оценка

Автоматическая рубрика сопоставляет ответ с вычисляемыми ожиданиями, а не с самооценкой модели. Покрываются допустимые ссылки, тип высказывания, знак и масштаб изменения, отделение наблюдения о релизе от причинности и наличие проверяемого действия.

- Синтетическое падение. Основной индекс снизился на 30%, контроль остался стабильным. При независимой тестовой Метрике с ростом визитов на 20% в тех же календарных окнах сервер сохраняет противоречащий сигнал. Гипотезы по правилам разделяют проблему измерения и барьер после изменения.
- Синтетическая стабильность. Одинаковые значения до и после не превращаются в сигнал падения или задачу «исправить падение».
- Синтетические пропуски. При недостающей неделе отчёт сохраняет null. Отсутствующую контрольную группу не заменяет средним другой группы.
- Неуспешный эффект. Рост основной метрики при нарушении согласованного побочного показателя оставляет статус inconclusive. Без полного окна вывод об эффекте не формируется.
- Непрофильный вопрос не раскрывает данные расследования.

Отдельный тест объединяет заказы, Метрику, конкурентные материалы, CustDev, релизы и бэклог. Тестовый адаптер получает только разрешённые публичные аргументы. Его результат помечен как синтетический. Проверка API с тестовым сервером модели подтвердила последовательность инструментов, неизвестные ссылки, восстановление после невалидного JSON и сохранение результата.

## Регрессионные и интеграционные проверки

- Базовый спринт — 25 из 25 тестов.
- Текущий набор — 48 из 48. Есть отдельные сценарии параллельных импортов, идемпотентного согласования, независимых порогов, сохранения после перезапуска, отсутствия Метрики и пустого или отключённого поиска.
- Синтетическая рубрика без модели — 4 из 4. Разрешённые тестовые данные отделены от реальных.
- Шесть параллельных клиентов сформировали 24 независимых отчёта через HTTP. Все 24 записи сохранились в одной SQLite и отразились в сводке.
- Отдельный запуск приложения с интервалом 60 секунд сохранил отчёт и связанное уведомление за 61,17 с. Браузер не открывался.
- Браузерный QA проверяет старый обзор, локальные исследования, отчёт агента, сохранение задачи, журнал, дневную сводку и симуляцию на настольной и мобильной ширине. Синтаксис JavaScript и автономная сборка входят в прогон.

Живой Qwen3-0.6B Q8_0 проверен на CPU через llama.cpp b12800. Первые прогоны сценария падения обнаружили, что модель подставляла идентификаторы вместо действий и иногда не укладывалась в таймаут. Схема последнего шага теперь оставляет модели формулировку возможной причины, проверку, ожидаемое наблюдение и ссылки. Остальные поля собирает сервер. На обновлённой схеме модель самостоятельно выбрала продажи, релизы и исследования, вернула валидную гипотезу и прошла рубрику сценария падения за 49,928 с и 6859 токенов. В заключительных сценариях модель выбрала проверку продаж, а сервер завершил численный ответ без лишней генерации гипотез. Стабильность проверена за 6,124 с и 1268 токенов. Пропуски проверены за 4,232 с и 1049 токенов. Явно непрофильный запрос обработан за 0,010 с без использования модели или источников. Все четыре сценария прошли рубрику, для одного из них проверялся полноценный синтез живой гипотезы. Измеренная стоимость локального исполнения не установлена. Для оценки по заданному тарифу умножьте время выполнения в часах на стоимость машинного часа.

## Недочёты и оставшиеся ограничения

- До спринта шаг модели переставлял заранее собранный контекст. Мониторинг только замечал порог. Ссылки проверялись формально, даже если источники относились к разным периодам. Эти части заменены контролируемыми вызовами, транзакционным мониторингом и проверяемыми сопоставлениями.
- Качество русскоязычной формулировки и причинность требуют ревью. Валидный JSON подтверждает технический контракт и ссылочную целостность, но не доказывает продуктовый вывод. Браузер и сервис рассчитаны на локальный запуск. Нагрузочный тест многодневного сервиса не проводился.
- Qwen3-4B, закрытый эталон Softline и живые вызовы рабочей Метрики не прогнаны. Утверждённые веса и доступ к локальным источникам и ключам не были настроены. Эталонный лист исключается из retrieval и импорта; при получении доступа его можно открыть для отдельного сравнения после выполнения расследования.
- PDF со сканами требует подготовки OCR. Ввод Excel расходует только явно разрешённый диапазон. Экспорт Redmine локальный, корпоративных записей не делали.

## Запуск и интеграция

Установите зависимости командой python -m pip install -r requirements.txt в отдельной среде. Задайте PM_PRIVATE_DIR вне рабочего дерева и запустите python app.py serve. Для проверки используйте python -m unittest discover -s tests -v, python scripts/qa_browser.py и python scripts/ai_quality.py. Для живой рубрики запустите утверждённый llama-server через scripts/run_model.py, задайте PM_LLM_URL на loopback, затем выполните python scripts/ai_quality.py --live. Команды для Windows и Linux есть в [инструкции](docs/ai_handoff.md).

После согласованной интеграции feature/yandex-search проверьте наличие pm/web_search.py и настройте публичный каталог, домены и темы по .env.example. Синтетический тест и режим без поиска должны сохранять результат до включения живого API. Включение живого поиска выполняется отдельным настроенным прогоном. Контракт v1 сохранён. [Контракт API](docs/ai_contract.md)
