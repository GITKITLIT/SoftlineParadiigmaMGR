# Проверка аналитического качества Qwen

## Рубрика

Каждый критерий оценивается по исходным данным и фактическому отчёту. Используйте 0 для ошибки или пропуска, 1 для частичного выполнения, 2 для выполнения. Для неприменимого критерия оставьте пропуск с причиной.

| Критерий | Признак выполнения |
| --- | --- |
| Факты | Указаны продукт, измеренное событие и окно. Наблюдения привязаны к источнику. |
| Числа | Сходятся формула, единицы, знаменатель, покрытие и границы полных периодов. |
| Обоснованность | Корреляция, выброс или совпадение с релизом не представлены доказанной причиной. |
| Ссылки | Идентификаторы существуют и смысл цитаты поддерживает высказывание. |
| Независимость | Учтены разные исходные группы. Повторные выдержки одного документа считаются одной группой. |
| Факты и гипотезы | Гипотезы проверяемы, прошлые решения помечены как исторический контекст. |
| Альтернативы | Рассмотрены разумные конкурирующие объяснения и противоположные сигналы. |
| Польза | Первое действие воспроизводимо и разделяет причины до разработки. |
| Неопределённость | Указаны пропуски, ограничения контрольного ряда, неизвестные условия и устаревшие данные. |
| Галлюцинации | Нет вымышленных метрик, источников, причин, исторических значений и рыночных долей. |

Автоматические проверки в `scripts/qwen/evaluate.py` покрывают структуру, численную часть, разграничение синтетики, доступность источников, наблюдаемые эффекты, работу диалогового контекста и отдельные правила рубрики. Аналитическое соответствие причины и ссылки проверяется человеком. Успешный JSON сам по себе оценивает формат.

## Эталон R-09

Запустите независимую проверку после окончания расследования.

```sh
python scripts/qwen/run_release.py \
  --question 'Почему снизились заказы? Сверь релиз, контроль, воронку, интервью, конкурентов и бэклог.' \
  --output "$QWEN_PRIVATE_STATE/report.json"
python scripts/qwen/audit_release.py --workbook "$PM_WORKBOOK" \
  --case "$PM_CASE_CONFIG" --report "$QWEN_PRIVATE_STATE/report.json"
```

Скрипт читает `Продажи`, `Релизы` и `Метрики_данные`. Эталонный лист исключён из поиска и контекста. Параметр `--private-numbers` выводит расчёты для закрытой приёмки. Рабочие файлы, источники, точные замеры из материалов Softline и генерации модели храните вне Git.

Проверяйте отдельно дату выката, длину окон и неполную неделю, изменение индекса по основному и ориентирному рядам, покрытие по устройствам и два разных идентификатора задач. В книге v17 `cfg_reach_rate` определяется как визиты с конфигуратором относительно визитов на страницу семейства. Покрытие этой метрики не восстанавливает неизвестную конверсию в корзину. Патч показывает отдельный учёт `cfg_add_to_cart_rate`. При отсутствии записей для выбранного продукта результат по конверсии неизвестен. Длина базового окна учитывается при сопоставлении с прежними способами расчёта. В текущем Core база для планирования эффекта вычисляется по последним четырём полным неделям базы, а прежняя сводка усредняла скользящий четырёхнедельный индекс по всему базовому интервалу.

## Промпты

Встроенные инструкции AI Core сначала проверялись без вмешательства. Два дополнительных текстовых варианта не исправили финальный отказ на одинаковых доказательствах R-09. Эксперимент с ограничением символов в JSON Schema в части вызовов вернул ошибку встроенного парсера llama-server. В проверенном варианте численные значения для гипотезы заменяются качественными признаками, а факты с числами остаются в полном отчёте. Используйте [инструкцию синтеза](../llm_lab/prompts/synthesis-grounded.ru.txt). Планирование продолжает использовать штатную инструкцию, а отображение выжимки, расчёт эффекта и согласование выполняет Python.

Файлы `tool-selection.ru.txt` и `task-and-effect.ru.txt` содержат кандидаты для отдельного сравнения. Для проверки меняйте один параметр и запускайте те же сценарии. Фиксируйте качество, долю валидных ответов, токены и время. Если ускорение достигается за счёт потери независимого подтверждения, сравнение не пройдено.

## Границы доверия

Инструменты модели ограничены реестром Core и принимают строго проверенные параметры. SQL, секреты, хранилище резервных копий, создание и удаление задач и системные операции отсутствуют в реестре. Публичные данные остаются наблюдениями. Внешнему адаптеру передаётся только разрешённый продукт, домены и темы из каталога. Правки задачи проходят через отдельное действие пользователя. История и статусы чата привязаны к владельцу. Сервер показывает фактические шаги и ID доказательств. Внутренние рассуждения модели в журнале не собираются.

Проверки изоляции, повреждённого JSON, ошибочных ссылок и недоступности выполняются через локальные тесты и отдельные фикстуры. Для боевого корпоративного доступа требуется проверить аутентификацию и уровни доступа на интеграционном стенде.
