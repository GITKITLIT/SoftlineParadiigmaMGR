# Схема продуктовой БД

Текущая версия SQLite определяется PRAGMA user_version. Миграция v4 → v5 выполняется в явной транзакции с включёнными внешними ключами. Прерывание не фиксирует частичное DDL. На сервере PM_MIGRATION_STATUS_FILE требует независимую проверенную копию остановленной исходной БД. При отказе используйте инструкцию администратора вместо ручного редактирования номера схемы.

| Группа таблиц | Назначение |
|---|---|
| memory_sources, memory_series | Режим, источник, продукт, объект, метрика, метод, единица, сегмент, часовой пояс и измерения. Составной уникальный ключ разделяет несопоставимые ряды. |
| memory_observations | Число хранится в REAL с NULL для отсутствующего значения. Область наблюдения, дата события, получение, фиксация, проверка, версия, качество и связь supersedes хранятся раздельно. JSON используется для расширенных атрибутов. |
| memory_documents, memory_document_versions, memory_fragments | Документ, неизменяемая версия и локатор выдержек. Идентичный импорт обновляет время проверки. FTS5 индексирует отрывки при доступности, иначе используется ограниченный параметризованный поиск. |
| runs, memory_run_evidence, memory_hypotheses | Отчёт и связи с доказательствами. Гипотезы имеют отдельный тип. Новый вывод модели не создаёт численное первичное наблюдение. |
| tasks, idempotency, reviews | Согласование или отказ, критерии, ключ повтора и измерения эффекта. Синтетическая оценка не записывается как фактический эффект. |
| monitor, investigation_queue, memory_sync_jobs, memory_audit | Пороговые сигналы, ограниченная очередь, аренда и статусы сбора, аудит новых версий. |
| imported_evidence | Совместимое представление последних отрывков. Полная версия находится в memory_document_versions. |

Модели не предоставляется SQL-интерфейс. Запись выполняется в SQLite backend-кодом; роль администратора и файловые разрешения отдельны. Исторический срез as_of выбирает последнюю записанную версию каждого окна на дату фиксации знаний. Потенциальная цена хранится с URL, условиями, публикацией и датой получения. Получение публикации позже даты события сохраняет оба времени.

Импортированный исторический JSON содержит массив объектов с полями stream, source, product, metric, unit, start, value, quality. Необязательные поля включают end, subject, event_date, retrieved, aggregation, segment, timezone, method, metadata, dimensions и reference. Режим выбирается флагом CLI. Используйте quality complete только для проверенного полного окна. Для цен используйте stream competitor, subject, metric price, aggregation snapshot и dimensions с условиями предложения. Коррекция более ранней даты получения требует явного поля correction после ручной проверки.

В PostgreSQL сохраняйте логические ключи и порядок миграций, замените UTC-строки на TIMESTAMPTZ, календарные окна на DATE, индексы FTS на tsvector с конфигурацией языка. Приведите представление JSON к JSONB и добавьте отдельные роли аренды задач, чтения, записи и резервного копирования. Перед переключением сверяйте число версий, журнал связей, пропущенные значения и результаты синтетических и утверждённых рабочих сравнений. PostgreSQL не развёртывался.
