## Подключение

Адаптер AI Core проверяет флаг и формирует входы из собственного доверенного публичного каталога. Свободный вопрос, исходные документы, внутренние метрики, тексты интервью и идентификаторы бэклога остаются внутри локального расследования. Модуль повторно проверяет продукт, домены и темы. Ленивый вызов после проверки на стороне AI Core может выглядеть так.

```python
from datetime import UTC, datetime


def web_evidence(*, enabled, catalog_product, competitor_domains, topics):
    def disabled(reason):
        return {
            "schema_version": 1,
            "status": "disabled",
            "reason": reason,
            "source": "yandex_search",
            "retrieved_at": datetime.now(UTC).isoformat(timespec="seconds").replace("+00:00", "Z"),
            "items": [],
            "warnings": [],
            "usage": {"requests": 0, "cache_hits": 0},
        }

    if not enabled:
        return disabled("search_disabled")
    try:
        from pm.web_search import collect_competitor_evidence
    except ModuleNotFoundError as exc:
        if exc.name == "pm.web_search":
            return disabled("adapter_not_installed")
        raise
    return collect_competitor_evidence(
        product=catalog_product,
        domains=competitor_domains,
        topics=topics,
    )
```

Публичная сигнатура модуля:

```python
def collect_competitor_evidence(
    *, product: str, domains: list[str], topics: list[str]
) -> dict:
    ...
```

Поддерживаемые темы `pricing`, `licensing`, `checkout`, `product_features`, `support`. Имя продукта сверяется с каталогом после NFC-нормализации и схлопывания обычных пробелов. Сверка доменов точная после IDNA-нормализации. Каждый поддомен перечисляется отдельно. Каждый запрос содержит `site:<domain>`, публичное имя с явно настроенными вариантами и группу тематических синонимов. URL сверяется с доменом запроса. Для каждой темы первыми проверяются разные домены, чтобы небольшой бюджет охватывал несколько конкурентов. `coverage` отражает выполненные и пропущенные комбинации.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `YANDEX_SEARCH_ENABLED` | `false` | Включает сбор. Флаги принимают `true` и `false`. |
| `YANDEX_SEARCH_FOLDER_ID` | пусто | ID каталога Yandex Cloud. |
| `YANDEX_SEARCH_API_KEY` | пусто | API-ключ сервисного аккаунта. |
| `YANDEX_SEARCH_ALLOWED_DOMAINS` | `[]` | JSON-массив до 50 публичных доменов и явно разрешённых поддоменов. |

| `YANDEX_SEARCH_MAX_RESULTS` | `5` | От 1 до 100 отобранных документов на запрос. REST забирает до удвоенного числа кандидатов в пределах 100 за один вызов. |
| `YANDEX_SEARCH_MAX_QUERIES_PER_RUN` | `5` | От 1 до 50 уникальных запросов в плане и столько же фактических сетевых попыток суммарно, включая повторы. |
| `YANDEX_SEARCH_DAILY_LIMIT` | `20` | От 1 до 10 000 сетевых попыток за сутки UTC на одну БД. |

| `YANDEX_SEARCH_LIVE_SMOKE` | `false` | Разрешает CLI `--live` вместе с основным флагом. |
| `PM_PRIVATE_DIR` | `~/.paradiigmamgr` | Каталог для `yandex-search.sqlite3`. Для всех экземпляров с общим бюджетом используйте одну локальную БД и одинаковые лимиты. |

В Yandex Cloud применяется сервисный аккаунт с ролью `search-api.webSearch.user` и API-ключом с областью действия `yc.search-api.execute`. Ключ передаётся процессу через защищённую конфигурацию. Метрика использует собственные учётные данные. Транспорт обращается к фиксированному `https://searchapi.api.cloud.yandex.net/v2/web/search` напрямую по TLS, с системным хранилищем доверия и таймаутом операций 5 секунд. Перенаправления отклоняются. [Настройка доступа](https://aistudio.yandex.ru/ru/docs/search-api/quickstart/) · [Схема REST](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search) · [Синхронный поиск](https://aistudio.yandex.ru/ru/docs/search-api/operations/web-search-sync) · [Операторы запросов](https://aistudio.yandex.ru/en/docs/search-api/concepts/search-operators)

У запроса максимум три попытки. Для временных сбоев есть ограниченная задержка со случайным разбросом, учитывающая `Retry-After`. При длинном `Retry-After` повтор пропускается. Число попыток резервируется атомарно до отправки. При завершении процесса между резервированием и отправкой резерв сохраняется. Кеш сохраняет пустую выдачу и исходное время получения. Одновременные обращения к одному ключу внутри процесса совместно используют успешный кеш. Между процессами один и тот же холодный запрос может быть отправлен дважды в пределах общего дневного лимита.

## Контракт ответа

Пример синтетической записи из `python scripts/search_smoke.py`. В офлайн-сценарии единица в `usage.requests` соответствует одному вызову эмулятора.

```json
{
  "schema_version": 1,
  "status": "ok",
  "reason": null,
  "source": "yandex_search",
  "retrieved_at": "2026-11-27T00:00:00Z",
  "items": [
    {
      "id": "web:ea1682b72de40583319ee1e42994dd67",
      "kind": "competitor_web",
      "ref": "https://example.com/demo-pro",
      "title": "Демо Pro · синтетический пример",
      "text": "Подбор лицензии: 1 устройство, 12 месяцев; Путь покупки: выбор лицензии перед корзиной.",
      "url": "https://example.com/demo-pro",
      "domain": "example.com",
      "retrieved_at": "2026-11-27T00:00:00Z",
      "published_at": null,
      "content_type": "snippet",
      "topic": "licensing",
      "query": "site:example.com \"Демо Pro\" (\"лицензия\"|\"подписка\"|\"продление\")",
      "product": "Демо Pro"
    }
  ],
  "warnings": [],
  "usage": {"requests": 1, "cache_hits": 0},
  "metrics": {"elapsed_ms": 41.8, "cache_lookups": 1, "cache_hit_rate": 0.0}
}
```

- `ok` означает успешную обработку, включая пустую выдачу и XML-код `15`. `partial` возвращает пригодные результаты выполненных запросов и код первого ограничения или сбоя остальных запросов.
- `disabled` используется при выключенном флаге, отсутствующих списках или учётных данных, либо недействительной конфигурации. `unavailable` охватывает проблемы доступа, транспорта и бюджетов. `error` используется для неверного входа, отклонённого запроса или ошибочного формата ответа. Поля `reason` и `warnings` содержат машинные коды.
- `id` зависит от нормализованного URL без якоря и текста. Поле `matches` перечисляет темы, запросы и время получения при совпадении фрагментов. `retrieved_at` у элемента относится к исходному получению. Явная дата без времени сохраняется отдельно как `published_date` или `modified_date`. `modtime` даёт дату изменения. `published_at` требует явного времени публикации с часовым поясом.
- `snippet` означает поисковый фрагмент. `page_excerpt` хранит извлечённый фрагмент проверенной публичной страницы или её явно размеченных данных. Прямой HTTPS-доступ требует отдельного флага и списка разрешённых доменов. При блокировке сохраняется сниппет. Поисковые запросы всегда выполняет Yandex Search API.
- `metrics.cache_hit_rate` рассчитывается от числа обращений к включённому кешу. Без обращений значение равно `null`. `elapsed_ms` включает ожидание повторов и работу SQLite. [Форматы ответа](https://aistudio.yandex.ru/ru/docs/search-api/concepts/web-search) · [Коды ошибок](https://aistudio.yandex.ru/ru/docs/search-api/reference/error-codes)

## Импорт и контекст для Qwen

`pm.competitor_sources.load_competitor_evidence(path: str | os.PathLike[str], *, limit: int = 200) -> list[dict]` принимает XLSX и PPTX. Лимит от 1 до 2000. Результат содержит `id/ref/text/kind`, где `kind="Конкуренты"`, имя файла, лист и диапазон либо номер слайда в порядке презентации, а также дату импорта. Поля предложения, конкурент, дата исследования, метрика и единица извлекаются из распознанных явных заголовков или подписей. Для XLSX значение берётся из ячейки или сохранённого результата формулы, если он есть. Пустые ячейки и пустые продолжения объединённых ячеек остаются пустыми. Используется до первых 10 000 строк и 80 столбцов каждого листа. «Эталонный_кейс» и варианты его написания с разделителями пропускаются. PPTX даёт текст слайдов в порядке презентации. Входной архив ограничен 20 МиБ, распакованные компоненты 64 МиБ суммарно. Архив не извлекается на диск. Некорректный формат или превышение лимитов вызывают `ValueError`, ошибки чтения файла — `OSError`.

CLI пишет новый JSON в существующую папку вне Git. `PM_EVIDENCE` указывает на один корпус. Для сохранения остальных материалов объединяйте массивы записей в локальной копии корпуса с дедупликацией по `id`.

`pm.yandex_search.comparison.build_comparison_context(web_result=..., local_evidence=..., own_evidence=...)` принимает результат v1, записи импорта и необязательную внутреннюю запись предложения. Для внутренней записи нужны `id`, `ref` и фактически известные поля. Условия предложения задаются через `product`, `version`, `license_type`, `duration`, `devices`, `tax`, `currency`, `price`, `study_date`. Контекст содержит источники и даты, неизвестные и различающиеся условия, признаки наличия, подбора лицензии, пути покупки и консультации. Разность цен выводится для предложений с одинаковыми явными условиями и датой сравнения при достаточном типе источника. Для поискового фрагмента с совпавшими условиями нужна проверка первоисточника. Текстовые наблюдения передаются как недоверенные данные, гипотезы формируются отдельно.

Для локального Qwen передавайте ограниченное число релевантных наблюдений. Формат вывода модели может включать характеристику, внутренний источник для собственного продукта, ссылку и дату конкурента, различие или отсутствие данных, сопоставимость, возможное влияние на UX и способ проверки. Поисковая позиция описывает ранжирование выдачи. Для рыночной доли нужны отдельные данные. Утверждение о цене проверяйте по первоисточнику и по условиям предложения.

Снимок сохраняется через `scripts/search_smoke.py --snapshot PATH` или `write_private_json(PATH, result)` для полного ответа сборщика. Каждый новый файл подтверждает один запуск и хранит времена источников. Исследование и свежий снимок можно сравнивать в одном контексте с их исходными датами.

После объединения веток сначала выполните общий набор тестов и `scripts/search_investigation_smoke.py`. Этот сценарий проводит синтетический сигнал, связанный бэклог, локальное исследование и поисковый фрагмент через текущий локальный поиск. Затем проверьте в адаптере AI Core, что контракт v1 потребляется с положительным ответом и статусами `disabled`, `partial`, `unavailable`. Живой запрос согласовывается отдельно. При настроенных и разрешённых учётных данных выставьте оба флага в `true` и запустите один раз.

```text
python scripts/search_smoke.py --live --product "<разрешённое имя>" --domain "<разрешённый домен>" --topic licensing
```

Live smoke проверяет одну комбинацию, обходит кеш, резервирует один запрос и отключает повторы. При успешной пустой выдаче завершение с кодом 0 корректно. Отсутствие согласованного бюджета, ключа или разрешённого доступа блокирует live smoke. Зашифрованные или нестандартные файлы Softline следует проверить отдельно на разрешённой локальной копии.

## Тарификация и результаты

По документации, проверенной 27.11.2026, тариф в рублях с НДС для синхронного поиска составляет 488 ₽ за 1000 дневных и 366 ₽ за 1000 ночных запросов. Льготное окно для этого тарифа — с 00:00 до 07:59:59 UTC+3. Единица тарификации — запрос. Провайдер указывает, что ошибки авторизации и внутренние серверные ошибки не тарифицируются. Локальный лимит считает все зарезервированные попытки. [Официальная тарификация](https://aistudio.yandex.ru/ru/docs/search-api/pricing)

На ревизии первого спринта `35792ff` проверены 44 теста, включая HTTP на loopback с реальным обменом запросом, повтором после 503 и чтением из кеша. TLS-настройки транспорта и отказ от перенаправлений покрыты тестами клиента. Node.js проверил `web/app.js`, браузерный сценарий получил `UI PASS`. За 30 офлайн-повторов медиана составила 41,75 мс с новой БД и 5,85 мс при повторном чтении из кеша, 30 попаданий из 30 и ноль повторных вызовов имитатора. Сетевой отклик Яндекса эти числа не измеряют.

Доступ Yandex Search API в корпоративном контуре и реальная структура закрытых материалов Softline требуют отдельной проверки. В этом запуске ключи, бюджет live smoke и разрешённые локальные пути к файлам Softline отсутствовали. Совместный backend AI Core и локальная модель Qwen в этой рабочей копии не запускались.
