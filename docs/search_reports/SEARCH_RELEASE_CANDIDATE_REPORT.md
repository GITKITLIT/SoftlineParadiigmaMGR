## Передача AI Core и PIM

Публичная сигнатура `pm.web_search.collect_competitor_evidence(*, product, domains, topics)` сохранена. Запрос формируется доверенной конфигурацией с явными доменами и темами. Опубликованная AI Core уже вызывает сборщик при переданном `web` и умеет хранить полученные записи через собственный `record_web`. Поисковый кеш остаётся операционным, со сроком жизни. Предыдущие конкурентные снимки остаются в своей существующей истории.

Для переноса снимков в существующую PIM вызывайте адаптер из доверенного процесса AI Core. `history_batch` читает историю без записи и возвращает снимок, его прежний пригодный снимок и курсор. `project_snapshot` строит список штатных наблюдений PIM. `write_pim_snapshot` использует транзакцию `ai_store.database` и `memory.observation` опубликованной AI Core. Схему, основную БД и HTTP-маршруты определяет AI Core.

```python
from pathlib import Path
from pm.yandex_search.pim import history_batch, write_pim_snapshot

for entry in history_batch(Path(approved_history_dir), after=committed_cursor):
    applied = write_pim_snapshot(entry["snapshot"], entry["previous"], mode="local")
    # Persist entry["cursor"] after the committed transaction succeeds.
```

Для синтетических данных задайте `mode="synthetic"`. Для реального импорта используйте авторизованную рабочую PIM. Переносите в порядке курсора. При повторе стабильный `metadata.observation_id` возвращает уже записанный PIM ID, в том числе после добавления более новой версии. Параллельные записи сериализует транзакция AI Core. Различающиеся снимки получают разные идентификаторы. Сопоставимость цен удерживается в ключе серии, включая валюту и условия предложения.

| Смысл | Поля |
| --- | --- |
| Продукт, конкурент, версия, характеристика | `product`, `subject`, `metric`, `metadata.product_version`, `metadata.observed_value`. |
| Цена и условия | `value` и `unit` для подтверждённой цены с полными условиями. Исходное десятичное значение, лицензия, валюта и покупка сохраняются в `metadata` и стабильных измерениях ряда. |
| Время и источник | `metadata.observed_at`, `retrieved_at`, `captured_at`, `source_url`, `source_type`, `sources`. Для локального документа сохраняются координаты и время импорта, когда они есть. Отсутствующие даты остаются `null` в метаданных. |
| История и качество | `observation_id`, `snapshot_id`, `previous_snapshot_id`, `previous_observation_id`, `reliability`, `change`, `alternatives`. При множестве ссылок сохраняются их ID и полный основной источник. |
| Неизвестные данные | `quality=missing`, `metadata.reliability=unknown`, `value=null`. Сниппеты, устаревшие, противоречивые и несопоставимые цены не попадают в числовой ряд подтверждённых цен. |

История PIM хранит даты наблюдений разных лет. В опубликованном API окно отдельного чтения ограничено 1 096 днями и задаётся массивом `["YYYY-MM-DD", "YYYY-MM-DD"]`. Веб-свидетельства текущего расследования и исторический перенос различаются по исходному коду ряда и происхождению.

## Финальный аудит безопасности

- HTTPS-проверка повторно валидирует каждый переход, DNS-ответ и фактический адрес соединения. Локальные адреса, метаданные, нестандартные порты и перенаправления за пределы доменов запроса блокируются. В тестах отдельного запроса защиту проверили в том числе на переходе к другому домену из общего списка.
- Скачивание соблюдает `robots.txt`, при блокировке и `Retry-After` отступает, ограничивает размер, MIME и задержку. Loopback проверил повтор после 503 и прекращение медленной передачи заголовка. Проверки TLS завершаются ошибкой при несовместимом адресе или сертификате.
- Поисковые запросы состоят из одобренного каталога и ограниченных параметров. Ссылки с полями сессии или секрета фильтруются, включая выдачу из прежнего кеша. Заголовок авторизации предназначен только для Yandex Search API. В PIM и Qwen идут нормализованные фрагменты без исходного HTML. Распознаваемые строки с инструкциями исключаются из цитат и полей утверждений для Qwen. Оставшийся публичный текст всё равно считается недоверенными данными.
- Параллельные вызовы, срок кеша, дневной бюджет, повтор снимка и интервальная блокировка мониторинга проверены синтетическими регрессиями. Рабочие базы, секреты и материалы Softline не входят в diff.
