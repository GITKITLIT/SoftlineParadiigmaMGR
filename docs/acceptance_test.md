# Приёмка Release Candidate

## Репетиция на отдельном состоянии

1. Создайте отдельное виртуальное окружение и установите requirements.txt. PM_PRIVATE_DIR должен быть отдельным временным каталогом вне Git. Для демонстрации оставьте METRIKA_TOKEN, PM_WORKBOOK, PM_SNAPSHOT и YANDEX_SEARCH_ENABLED пустыми.
2. Запустите python -m unittest discover -s tests -v. Для браузера выполните python scripts/qa_browser.py с Playwright и Chromium, которые описаны в README.
3. Запустите python scripts/pim_acceptance.py. Сценарий запускает локальный HTTP, обнаруживает синтетическую аномалию, проверяет доказательства и гипотезы, согласует задачу, запускает симуляцию эффекта, делает снимок и проверяет восстановление после потери исходного экземпляра. После восстановления проверяет историческое число, связи, выдержки и новую запись. Скрипт сам изолирует временное состояние.
4. Для интерактивного демо выполните python app.py serve. На демонстрационных данных откройте «ИИ-агент». После анализа согласуйте предложенную задачу, задайте цель 110 и загрузите data/effect-demo.json в симуляцию. В базе знаний выберите синтетические данные и откройте доступные исторические ряды. До использования рабочего данных выполните разрешённый импорт.
5. Для Qwen3-4B укажите утверждённый loopback endpoint и выполните python scripts/ai_quality.py --live. Для проверки прошлогоднего окна заранее загрузите два сопоставимых ряда через import-history и запустите исторический анализ из «База знаний». Проверьте фактический инструмент в журнале. При пропуске периода delta должен быть null.

## После согласованного слияния Yandex Search

1. Проверьте сигнатуру collect_competitor_evidence с аргументами product, domains, topics. Сохраняйте ответ schema_version=1. Никаких автоматических merge в этом этапе.
2. Повторите общий набор Python и оба офлайн-скрипта search_smoke.py и search_investigation_smoke.py. Проверьте режим без поиска, пустой ответ и один тестовый публичный снимок. В истории должно появиться наблюдение, чей URL и quality совпадают с ответом адаптера.
3. Проверьте два сопоставимых ценовых снимка с известными product, version, license_type, duration, devices, tax и currency. Изменение цены выводится, смена условий создаёт отдельный ряд. Истечение кеша не удаляет сохранённый снимок.
4. Лишь после настройки бюджета и разрешённого API проведите ограниченный живой smoke. Проверьте, что в adapter передаются только разрешённый публичный продукт, домены и темы.

## Рабочая приёмка

Подключите утверждённые выгрузки, даты релизов, источники и рабочий счётчик согласно [настройке памяти](product_memory.md). Сначала проверьте даты и рабочий контур Метрики отдельно от тестового счётчика. Сравните вывод с эталоном после расследования. Документируйте отсутствие серий, ключей и подтверждённых наблюдений. Для готовности к постоянной эксплуатации проверьте учётные записи, тиражирование, таймер, зашифрованный том, Object Storage и восстановление. [Процедура резервирования](backup_and_recovery.md)
