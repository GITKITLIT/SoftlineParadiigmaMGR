# Локальная приёмка Dashboard

Интерфейс основан на `release/pre-final` (`8f977754b67722a3181cc8243dceddb771ecc165`). Маршруты хранятся во фрагменте URL. Ссылки `#report=<id>` из уведомлений открывают сохранённый отчёт. Ссылки на доказательства сохраняют идентификатор отчёта и открываются после обновления страницы. При переходе между разделами элементы форм, чат и отчёт остаются в DOM.

## Запуск синтетического стенда

Из корня репозитория на macOS или Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
dashboard_state=$(mktemp -d)
env -i PATH="$PATH" HOME="$HOME" PM_PRIVATE_DIR="$dashboard_state" \
  PM_QWEN_CHAT_ENABLED=true PM_QWEN_OWNER_MODE=local \
  .venv/bin/python app.py serve --port 18180
```

Откройте [локальный Dashboard](http://127.0.0.1:18180/). Здесь используются синтетические ряды и отдельная база SQLite. Чат и расследования работают с локальным резервным анализом. Для остановки нажмите Ctrl+C в терминале.

## Ручные проверки

1. На обзоре сверьте карточки, график и сигнал по порогу. Перейдите в метрики и измените период, затем вернитесь на обзор.
2. Сверните одну группу, проверьте остальные, затем сверните весь Sidebar. Обновите страницу и проверьте восстановление настроек. На телефоне откройте меню, перейдите в раздел и проверьте закрытие по Escape.
3. Запустите расследование и перейдите в другой раздел. В верхней панели виден прогресс. Откройте завершённый отчёт из журнала, затем его доказательство. Обновите страницу по ссылке и проверьте кнопки браузера «Назад» и «Вперёд».
4. В чате создайте диалог, введите черновик, перейдите в другой раздел и вернитесь. Отправьте вопрос, откройте историю и убедитесь, что ответ сохранился. Черновик задачи можно согласовать в диалоге или из отчёта агента.
5. В бэклоге проверьте согласованную задачу и экспорт Redmine. Для проверки эффекта используйте синтетические наблюдения. В исследованиях проверьте поиск и импорт текста, в базе знаний — сравнение периодов и переход к агенту.
6. Проверьте историю релизов и цен через базу знаний. На синтетическом стенде возможны пустые выборки. В настройках Backend должен отвечать, а модель и платные источники будут показаны как ненастроенные.

## Автоматические проверки и скриншоты

```bash
.venv/bin/python -m unittest discover -s tests
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
PM_DASHBOARD_SCREENSHOTS=/tmp/paradiigma-dashboard-screenshots \
  .venv/bin/python scripts/qa_browser.py
```

Переменная `PM_CHROMIUM` позволяет указать путь к установленному Chrome. Браузерный прогон создаёт изолированную базу, проверяет CSP с увязанным хэшем интерфейса и делает 12 снимков разделов плюс два мобильных. Для HTTPS в согласованной сборке заново сформируйте конфигурацию через `scripts/deploy/render_proxy.py`, чтобы CSP соответствовала JavaScript. Контракты API и настройки внешних подключений остаются прежними.
