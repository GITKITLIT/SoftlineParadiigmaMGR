# Запуск Qwen3-4B и эксплуатация

## Локальный профиль

Проверен GGUF Qwen3-4B, 4 022 468 096 параметров, Q4_K_M, через llama.cpp 1.1.0, build 12774, commit `171527522`. Компьютер MacBook Air с Apple M5, 10 CPU-ядер, 10 GPU-ядер и 16 ГБ объединённой памяти. `llama-server --list-devices` вернул `MTL0: Apple M5` и Accelerate. Запуск использует Metal через `--gpu-layers 99`.

```sh
llama-server --model "$QWEN_GGUF" --alias Qwen3-4B \
  --host 127.0.0.1 --port 18081 --ctx-size 16384 --parallel 2 \
  --threads 4 --threads-batch 8 --gpu-layers 99 --reasoning off --cache-ram 512 --metrics
```

Команда предполагает, что `QWEN_GGUF` указывает на разрешённые локальные веса. `GET /health` возвращает готовность. `GET /v1/models` возвращает псевдоним и контекст 8192 токена на слот. Сервис приложения использует `PM_LLM_URL=http://127.0.0.1:18081/v1` и `PM_LLM_MODEL=Qwen3-4B`. Оставляйте модель на loopback. Доступ к приложению на тестовом Mac тоже локальный.

Для запуска из Python и без сети используйте существующие `requirements.txt` и `scripts/run_model.py`; по умолчанию никаких весов загружать не требуется. Параметры экспериментальной сборки и приватного контура описаны в [инструкции интеграции](chat_integration.md).

## Производительность и ресурсы

Стенд обрабатывает до двух активных расследований через штатный `live_runs`. В прогоне R-09 планирование занимало несколько локальных HTTP-вызовов. Каждый ответ на шаг планирования ограничен 120 токенами, финальный синтез 560 токенами. В экспериментальном синтезе интерпретируются словесные признаки изменения и качества, а фактические суммы, доли, условия и окна остаются в отчёте Python. Это уменьшило входной контекст финального вызова в парном сравнении R-09. Ограничения планировщика, таймаутов, валидатора и повтора остаются в AI Core.

RSS процесса по `ps` измеряет резидентную память процесса. Для Metal это частичная картина общей памяти системы. `vmmap -summary` показал 11,5 ГБ физического следа в полном прогоне с кэшем 8192 МиБ и 3,2 ГБ в повторе поднабора с кэшем 512 МиБ. Пропускная способность SSE измеряется отдельным коротким синтетическим запросом. AI Core использует структурированный JSON в обычном HTTP, поэтому чат показывает сохранённые события выполнения.

Для Максима начальный профиль проверки на Linux — локальные веса того же квантования, модель на loopback, один слот по 8192 токена и включение второго слота после нагрузочной проверки. При CPU-only задайте `--gpu-layers 0` и измерьте скорости и RSS на конкретном VPS. На машине без ускорителя производительность и предел конкуренции следует проверить отдельно. Вариант с 12–16 ГБ доступной памяти подходит для первого нагрузочного прогона Q4_K_M с приложением и SQLite. Это начальная оценка, результаты Linux не измерялись.

## Воспроизведение

```sh
python scripts/qwen/evaluate.py --mode fallback --concurrent
python scripts/qwen/evaluate.py --mode live --concurrent --server-pid "$LLAMA_PID"
```

Укажите PID только для собственного процесса. Второй запуск требует переменных модели из локального профиля. Для сопоставимости оставьте исходный шаблон GGUF и `--reasoning off`. Профиль ChatML проверялся на одном слоте. Он сохранял проблему исходного синтеза R-09 с цифрами в текстовых полях. Данные о длительности живых сценариев приведены в [отчёте](../QWEN_ENGINE_REPORT.md).

## Стоимость

`scripts/qwen/cost.py` использует агрегированный JSON живого прогона и заданную пользователем цену машинного часа. Нагрузка по умолчанию на одного продакта в неделю включает 15 простых вопросов, 10 уточнений, 2 первоначальные выжимки с формированием отчёта, 2 расследования, 2 исторических разбора, 1 конкурентный запрос и 2 черновика. Повторное раскрытие сохранённой выжимки не запускает модель. Мониторинг добавляет 7 расследований в неделю на весь стенд. Оценка модели пропорциональна сумме измеренного времени и числу запросов. Для постоянно работающего хоста стоимость аренды за неделю равна 168 машинным часам. Запуски, завершающиеся резервным ответом, учитывают фактически затраченное время, а повторные обращения увеличат нагрузку.
