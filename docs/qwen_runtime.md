# Локальная модель Qwen

PARADИИGMA работает с Qwen3-4B Q4_K_M через HTTP API llama.cpp. Укажите разрешённую локальную сборку и веса. Лаунчер проверяет SHA-256, привязывает модель к loopback и поддерживает ограничение числа слотов и потоков.

```bash
python scripts/run_model.py --server "$LLAMA_SERVER" --model "$QWEN_GGUF" --parallel 1
export PM_LLM_URL=http://127.0.0.1:18081/v1
export PM_LLM_MODEL=qwen3-4b PM_LLM_SELECT_STEP=true PM_QWEN_QUALITATIVE=true
```

По умолчанию используется контекст 8192 на слот. Для отдельного CPU-узла с одним слотом и четырьмя vCPU доступен вариант `--threads-batch 4 --gpu-layers 0`. Параметры и задержку подтвердите на своём оборудовании. При применении однослотового профиля Core задайте `PM_QWEN_RUNTIME_PROFILE=sandy-bridge-one-slot` и `PM_QWEN_STABLE_PLANNER_PREFIX=true`. Core запускает одно расследование одновременно и оставляет одно в ожидании. Браузер получает лимит ожидания от Backend.

Дополнительный [шаблон синтеза](../llm_lab/prompts/synthesis-grounded.ru.txt) можно скопировать в каталог оператора вне рабочей копии и указать через `PM_LLM_PROMPT_FILE`. Тайм-ауты и набор проверок задаёт код. При недоступном endpoint интерфейс показывает результат локального расчёта, а сохранённая история доступна через SQLite. [Проверки без модели](testing.md)

Для отдельного узла используйте существующие [шаблоны SSH](../deploy/ssh/). Модельный процесс и локальный порт клиента оставляйте на loopback. Защищённые настройки включают отдельную пару ключей, проверенный host key и разрешение только модельного форварда.
