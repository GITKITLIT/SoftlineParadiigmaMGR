# Продуктовая память

В одном приватном каталоге PM_PRIVATE_DIR хранится SQLite ai.sqlite3. История не привязана к браузеру, сессии или модели. Сервер и браузер открывают её через ограниченный API. Для работы с другого компьютера используйте тот же защищённый сервер либо отдельное восстановление копии. Файл не следует размещать на общей сетевой файловой системе без проверки гарантий блокировки.

## Настройка

Установите requirements.txt. В PowerShell задайте переменные через $env:ИМЯ, в Linux через export или защищённый EnvironmentFile. Список полей упорядочен в .env.example. Рабочий PM_PRIVATE_DIR задаётся вне репозитория.

- Qwen3-4B. Подготовьте утверждённые веса, затем выполните python scripts/run_model.py --server PATH_TO_LLAMA_SERVER --model PATH_TO_GGUF. Укажите PM_LLM_URL=http://127.0.0.1:18081/v1 и PM_LLM_MODEL=qwen3-4b. Для systemd используется paradiigma-qwen.service с отдельным пользователем модели. Сравнения чисел выполняет Python.
- Продажи. Укажите PM_WORKBOOK и PM_CASE_CONFIG или PM_SNAPSHOT. Встроенный импорт сохраняет недельные индексы и релизы. Для чисел заказов, выручки, сопровождаемого канала и дополнительных показателей подготовьте утверждённый файл наблюдений и выполните python app.py import-history --file PATH --mode local. Синтетическим данным явно задайте --mode synthetic.
- Метрика. Укажите METRIKA_COUNTER_ID, METRIKA_TOKEN, METRIKA_SCOPE и METRIKA_COUNTER_TIMEZONE. Тестовый счётчик хранится отдельно. Метрики посещаемости, отказы, время и настроенные цели сохраняются из ответа. Дополнительные официальные метрики, включая e-commerce, настраиваются в METRIKA_EXTRA_METRICS объектом с псевдонимом и полями code и unit. Сегменты определяются в METRIKA_SEGMENTS. База хранит псевдоним и отпечаток фильтра, чтобы технически различать изменения без сохранения контактного условия.
- Документы. Поддерживаются разрешённые диапазоны Excel, TXT, DOCX, PPTX и PDF с текстовым слоем. Используйте python app.py import --file PATH --kind Интервью --preview, затем без --preview для сохранения. Результаты из прежнего SQLite-индекса перенесены в историю версий. Прежний sources.json читается текущим поиском; для версии в памяти выполните повторный импорт. Эталонный лист исключается.
- Заметка оператора. В режиме рабочих данных введите сформулированное наблюдение в разделе «База знаний», при необходимости укажите продукт и дату, нажмите «Сохранить текст как заметку». Материал классифицируется как неподтверждённое сообщение. Контактные данные и известные шаблоны credentials отклоняются; оператор контролирует разрешённость материалов.
- Конкуренты. Долговременные снимки создаются при штатном расследовании через pm/web_search.py. Интерфейс v1 сохранён. Сниппеты не становятся подтверждённой ценой. Полная цена допускается для сравнения только при известной валюте и сопоставимых условиях. Исторические данные не зависят от поискового кеша.

PM_COLLECTION_INTERVAL=0 отключает периодический сбор. Для локальных продаж разрешён интервал 300–86400 с. PM_COLLECT_METRIKA=true разрешает отдельный сбор прошедшего дня. PM_METRIKA_DAILY_LIMIT ограничивает попытки сбора, а клиент выполняет не более одного повторного HTTP-вызова на попытку. Перезапуск продолжает планирование задач. Повторное историческое получение Метрики выполняется через /api/memory/sync с kind=metrika и day. Пользуйтесь выделенным лимитом счётчика. Планировщик не запускает модель или внешний конкурентный мониторинг. PM_DB_MAX_MIB ограничивает дальнейший рост файла SQLite без удаления истории; выставляйте лимит совместно с квотой диска и мониторингом свободного места.

## Исторические инструменты

В интерфейсе нажмите «База знаний». Выберите режим, исторический ряд и два окна. «Сравнить периоды» возвращает измерения и число изменения. «Исследовать с агентом» передаёт эту область разрешённому инструменту. Вопросы о ранее принятых решениях могут вызвать поиск по исследованиям и расследованиям. Предыдущие гипотезы идут как контекст. Сходная отклонённая гипотеза подавляется, если набор подтверждающих данных не изменился.

API принимает JSON через POST на loopback.

| Маршрут | Параметры |
|---|---|
| /api/memory/overview | mode |
| /api/memory/series | mode, product? |
| /api/memory/compare | mode, series_id, before и after по две ISO-даты, as_of?, denominator_series_id? |
| /api/memory/timeline | mode, series_id, period, as_of? |
| /api/memory/product | mode, product, period, series_id?, as_of? |
| /api/memory/competitors | mode, period, product? |
| /api/memory/search | mode, query, product?, kind?, start?, end? |
| /api/memory/note | text, product?, observed? |
| /api/memory/sync | kind sales или metrika, day? для Метрики |

Для доли укажите совместимые аддитивные ряды числителя и знаменателя. SQL сначала суммирует наблюдения внутри периода. Python рассчитывает долю и изменение в процентных пунктах. Нулевой знаменатель, пропуски, неподдерживаемая агрегация, соединение разных источников и неполный текущий день не дают ложной нулевой оценки. Разный недельный состав окон сопровождается предупреждением; сезонная поправка не вычисляется без достаточной статистики. Для уникальных посетителей, накопительных и взвешенных метрик используйте первичное наблюдение на всё окно. API не суммирует дневные уникальные значения или проценты.

В запросе расследования поле memory принимает mode и необязательные compare, competitors, product, search с теми же параметрами соответствующего инструмента. Инструменты может выбрать Qwen. Аргументы берутся из области, заданной оператором; модель не пишет SQL. Возврат ограничен по объёму. Если выбранный режим отличается от текущего рабочего набора, текущий набор в это расследование не подмешивается.
