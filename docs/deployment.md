# Развёртывание и восстановление

Поставка рассчитана на Ubuntu 24.04 с systemd. [Шаблоны установки](../deploy/) включают Backend, Qwen, Nginx, ограничения AppArmor и резервное копирование. [Зависимости](../deploy/requirements.lock) закреплены с хешами. Подготовьте проверенный локальный источник Git, целевую ревизию и утверждённые учётные записи до переключения экземпляра.

- [Установка](../scripts/deploy/install.sh) раскладывает ревизии и связывает конфигурацию служб. [Обновление](../scripts/deploy/update.sh) и [проверка кандидата](../scripts/deploy/check_candidate.py) используют точный SHA и ожидаемую версию схемы. Для тестирования этих сценариев предусмотрена одноразовая Linux-ВМ. [Workflow](../.github/workflows/deployment.yml)
- Храните настройки в защищённом окружении службы. [Шаблон окружения](../deploy/app.env.example) содержит ожидаемые переменные. Для Яндекс.Метрики, Search и SMTP используйте выделенные полномочия и контролируемые бюджеты. Держите эти интеграции выключенными в синтетическом демонстрационном экземпляре.
- Завершайте TLS на Nginx. Для персонального чата используйте режим `proxy` и доверенное имя пользователя. Штатный [рендерер](../scripts/deploy/render_proxy.py) формирует CSP для текущего JavaScript. Модель и Backend слушают loopback. Настройки и ключи SSH генерируются для конкретной площадки. [Шаблоны](../deploy/ssh/)
- Настройте резервирование отдельной ролью. Перед миграцией сохраните согласованную версию приложения и независимый проверенный снимок SQLite. Для безопасной проверки восстановите его в новый каталог. Штатный CLI принимает `verify --snapshot PATH` и `restore-test --snapshot PATH --output NEW_DIRECTORY`. [CLI](../scripts/pim_backup.py) · [Схема SQLite](database_schema.md)

Проверяйте готовность Backend, доступ к истории под двумя аккаунтами, доступность модели при её включении и независимое восстановление. Рабочая и демонстрационная SQLite должны находиться в разных каталогах состояния. Закрытые данные и ключи хранятся вне репозитория.



## Установка и проверка снимка

В выделенной Linux-среде задайте `APPROVED_SHA` полным SHA проверяемого коммита. Приведённые команды установки и обновления требуют прав администратора.

```bash
sudo bash scripts/deploy/install.sh "$APPROVED_SHA"
# Для установленного экземпляра используйте команду обновления.
sudo bash scripts/deploy/update.sh "$APPROVED_SHA"
```

Для автономной проверки состояния выполните команды из окружения с доступом к снимку. Каталог восстановления должен быть новым и располагаться вне используемой SQLite.

```bash
python scripts/pim_backup.py verify --snapshot "$SNAPSHOT"
python scripts/pim_backup.py restore-test --snapshot "$SNAPSHOT" --output "$NEW_DIRECTORY"
```

## HTTPS и проверка интеграций

GET главной страницы с query string перенаправляется кодом 302 на чистый HTTPS-адрес того же хоста. На чистом адресе действует Basic Auth. Запросы к API с query string получают 400. При смене шаблона проверьте редирект без авторизации, вход на чистый адрес и отклонение неверных Host и Origin.

Приёмка Метрики сверяет статус, период, источник и значения адаптера с ответом API. Для SMTP ответ реле 250 подтверждает приём письма. Доставку нужно подтвердить отдельно в целевом ящике.
