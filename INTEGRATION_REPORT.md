## Состав и разрешение конфликтов

- AI Core принят за основу с журналом, SMTP-очередью, PIM v6, аналитикой и бэклогом. Search добавлен коммитом `985a20d`. Публичный контракт остаётся `pm.web_search.collect_competitor_evidence(product=..., domains=..., topics=...)` с `schema_version=1`. Отдельный поисковый кеш не заменяет долговременные снимки PIM.
- Qwen добавлен коммитом `1279044`. Патчи `0001-chat-wiring`, `0002-qualitative-synthesis` и `0003-core-evidence` применены к коду один раз. Они подключают чат, выжимку, качественный контекст и ссылки на релизы, воронку и замеры. История диалога и временный прогресс защищены проверками владельца. Выжимка и чат могут читать один сохранённый отчёт.
- Deployment добавлен коммитом `1b9aa9d`. Пересеклись `paradiigma.service`, `paradiigma-backup.service`, `paradiigma-backup.timer` и `scripts/pim_backup.py`. Для них сохранён согласованный комплект Deployment с ролями pm-app, pm-qwen и pm-backup, отдельным vault, чтением WAL и проверкой восстановления. Недостающая проверка непустого WAL на стороне AI Core применена из `0002-pim-backup-compat.patch` без повторного применения изменений CLI. Старый unit модели заменён `paradiigma-qwen.service`.
- Патч `0001-qwen-proxy.patch` подключает служебные заголовки Nginx и хэш точного JavaScript, который выдаёт Backend. Preflight требует доверенного владельца для системной установки чата. Патчи хранятся с LF, что позволяет проверять их в Windows. В рабочем режиме интерфейс и поиск исключают встроенные демо-выдержки.
- Замер Windows CPU выявил тайм-ауты Qwen. Коммит `c3cfcdb` согласует ограниченный бюджет модели и опрос браузера. Коммит `a071071` отклоняет категоричные причины и требует опоры на основной ряд и второе наблюдение для гипотезы о падении заказов.

## Релиз и безопасность

На Ubuntu используйте единый [порядок установки, миграции и отката](docs/combined_release_deployment.md). Подготовлены отдельный контур жюри, настройки TLS и аккаунтов, запуск Qwen, Метрика, один Search-запрос с проверкой первоисточника и переносом в PIM, SMTP и проверка Object Storage. Список операторских действий и команды находятся в [эксплуатационной приёмке](docs/final_release_operator.md).

[Результаты автоматической, модельной и бизнес-приёмки](FINAL_ACCEPTANCE.md) содержат статусы и ограничения. Закрытые исходники и ответы R-09 обрабатывались на отдельном локальном состоянии вне Git. Публикация ограничена `origin/feature/integration`.

## Стоимость

Сформируйте приватный шаблон котировки, заполните цены поставщика для каждого сценария и передайте замер модели. Прямой расчёт нагрузки использует существующий `scripts/qwen/cost.py`.

```sh
python scripts/deploy/estimate_cost.py --template > "$QUOTE_FILE"
python scripts/deploy/estimate_cost.py --input "$QUOTE_FILE" \
  --qwen-benchmark llm_lab/benchmarks/mac-m5-live.json
```

Котировка учитывает VM приложения, отдельный узел Qwen, блочные диски, версии бэкапов, операции хранилища, IPv4, сеть, Search API и опциональный SMTP. Для общего узла отдельной VM модели задаётся нулевая аренда. Для тарифа с отдельной ценой машинного часа используйте `--model-hour-rub`. Укажите месячные количества для каждого сценария, включая утверждённые лимиты Search и SMTP.

| Продакт-менеджеры | Эквивалентная нагрузка Qwen в неделю по замерам Mac M5 |
| ---: | ---: |
| 1 | 0,1304 машинного часа |
| 5 | 0,4823 машинного часа |
| 35 | 3,1210 машинного часа |

Оценка нагрузки предполагает 34 запроса на менеджера и 7 фоновых расследований на стенд в неделю. Постоянно выделенная машина тарифицируется за всё время работы, например за 168 часов недели при почасовом тарифе. Вывод калькулятора показывает аренду и вычислительный эквивалент отдельно. Сумма в рублях зависит от утверждённой котировки и способа размещения. Производительность Linux VPS оценивается отдельным прогоном.
