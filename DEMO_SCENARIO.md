# PARADИИGMA · сценарий показа

Код основан на ревизии `c25dea94cd7c4a8a1b5696ffa812ff9fec3e7b8b`. `demo/rehearse.py` запускает этот код на loopback и хранит каждый прогон в отдельном каталоге `runs`. Используются встроенные продажи, воронка, релизы, бэклог, демо-выдержки и `data/effect-demo.json`. Для сравнения истории добавлены две синтетические точки 20 и 25 заказов с одинаковой методикой. Закрытый кейс R‑09 представлен только выводами ранее выполненной приёмки. [Матрица приёмки](BUSINESS_ACCEPTANCE.md)

## Запуск

Инструкция и команды подготовки доступны в [demo/README.md](demo/README.md). Для воспроизведения сохранённого результата сначала выполните локальную репетицию. База, браузерный сеанс и письмо создаются во временном каталоге системы.

## Порядок показа

| Шаг | Действие | Что увидит жюри |
| --- | --- | --- |
| 1. Сигнал | Откройте «Динамика индекса», затем «Журнал и задачи» → «Обновить». | Синтетический индекс падает на 30% при пороге 20%. Фоновое задание создаёт запись «Сигнал мониторинга». Кнопка ручной проверки для этого этапа не нужна. |
| 2. Расследование | У сигнала нажмите «Отчёт по сигналу». Разверните «Действия агента», «Доступность источников» и «Гипотезы Qwen». | В журнале видны выбранные Qwen инструменты и отдельные проверки сервера. В доказательствах покажите основной и контрольный ряды, релиз и воронку. Гипотеза содержит ссылку и способ проверки. Связь с релизом остаётся предположением. |
| 3. Источники | Откройте «Конкурентные источники» и «Релизы в расследовании». Покажите статус недоступных источников. | Выдержки и выводы синтетические. Для демонстрации доступны встроенные материалы. Живая Метрика и платный Search требуют отдельного согласования. |
| 4. Чат | Нажмите Q «Открыть чат Qwen». В новом диалоге задайте «Почему снизились заказы? Проверь воронку, интервью, конкурентов и бэклог.» Затем выберите «Контекст» → «Уточнение» и спросите «Как оценить эффект?». | Первый ответ приводит источники. Уточнение показывает ссылку «Предыдущий вопрос» и четырёхнедельный план из того же отчёта. При сохранённом показе раскройте два готовых ответа из истории. |
| 5. Черновик | На первом ответе откройте «Черновики задач». Задайте название «Сверить наличие позиции в корзине и регистрацию события», обновите «Способ проверки» и установите цель 110. | Видны база, контроль, источник и критерий. При необходимости спросите, достаточно ли доказательств для создания задачи или лучше изменить приоритет существующей. |
| 6. Согласование | Нажмите «Подтвердить сохранение в бэклоге». Сверните чат и откройте журнал после появления сообщения «Сохранено в серверном бэклоге». Если список пуст, нажмите «Обновить» один раз и дождитесь строки. | Появляется запись «согласована» с тегом «сгенерирована ИИ-помощником». Для заранее согласованной копии покажите сохранённую запись и скриншот шага. |
| 7. Экспорт | Для согласованной записи выполните запрос Redmine JSON из блока ниже или откройте результат репетиции. | Экспорт показывает локальный идентификатор, тег и JSON задачи либо предложение пересмотра приоритета существующей задачи. |
| 8. План | В уточнении раскройте «Как измерить эффект», затем соотнесите его с утверждённой целью 110. | Основной KPI сравнивается с базой за четыре полные недели, контрольный ряд остаётся отдельным. До появления наблюдений статус «Ожидаются четыре полные недели». |
| 9. Симуляция | В «Локальном бэклоге» у согласованной записи загрузите `data/effect-demo.json` через «JSON для симуляции». | Появляется «Симуляция · Рассмотреть закрытие после проверки» и новый индекс 120 при цели 110. Статус в JSON — `achieved`. Чтобы повторить показ после перезагрузки, загрузите файл снова. |
| 10. Почта | В журнале покажите «почта принято SMTP», откройте `notification.eml` и перейдите по ссылке на отчёт. | Локальное TLS-реле получило одно тестовое письмо после завершения расследования. Ссылка открывает сохранённое расследование. Внешний почтовый ящик в этой репетиции не использовался. |
| 11. PIM и живой запрос | «База знаний» → «Синтетические» → ряд «Демо · история заказов». Первое окно обе даты `2024-05-08`, второе обе `2025-05-08`. Нажмите «Сравнить периоды». Для живого запроса нажмите «Спросить в чате», затем «Спросить». | Python показывает 20 → 25, разницу +5 и +25%. В раскрытом ответе «Шаги расследования» показывает выбранное моделью сравнение истории. |
| 12. Повторный вход | Закройте демо и запустите `replay dress`. Снова откройте отчёт, диалог и бэклог. | Отчёт, диалог, согласование и исторические наблюдения загружаются из прежнего состояния. |

### Redmine JSON

```powershell
$site = 'http://127.0.0.1:18127'
$task = (Invoke-RestMethod "$site/api/tasks" -Method Post -ContentType 'application/json' -Body '{}').tasks |
    Where-Object { $_.decision -eq 'accept' -and $_.title -eq 'Сверить наличие позиции в корзине и регистрацию события' } |
    Select-Object -First 1
$body = @{ task_id = $task.id } | ConvertTo-Json -Compress
Invoke-RestMethod "$site/api/tasks/redmine-export" -Method Post -ContentType 'application/json' -Body $body |
    ConvertTo-Json -Depth 8
```

Для внешнего письма владелец Deployment согласует получателя, реле и одну попытку на отдельном синтетическом экземпляре. Не совмещайте тестовую команду и фоновую отправку в одном показе. При сценарии «падение → расследование → письмо» команда `email-test` не нужна. Наличие письма подтверждает владелец тестового ящика. Статус `submitted` показывает, что письмо принято реле.
