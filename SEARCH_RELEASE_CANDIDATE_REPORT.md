Ревизия кода кандидата — `a431b1f` в `feature/yandex-search`, исходная принятая ревизия второго спринта — `9d6bf52`. Коммит `b9db177` ужесточает область первоисточников, защиту SQLite и разделение результатов. `a431b1f` добавляет перенос неизменяемых снимков в PIM, компактную историю для Qwen, исключение явно обозначенных эталонных материалов и скрипт проверки композиции. Публичная сигнатура `pm.web_search.collect_competitor_evidence(product=..., domains=..., topics=...)` и контракт v1 сохранены. [Запуск, интеграция и передача](docs/search_release_handoff.md)

## Живая проверка и расходы

Предварительная проверка с публичным именем Kaspersky Endpoint Security, однопопыточным CLI и пустым набором ключей вернула `disabled / missing_credentials`, `usage.requests=0`, оценку 0,000 ₽. Платных обращений в этом задании было ноль. Реальная выдача для Kaspersky Endpoint Security, релевантность и ссылки провайдера, задержка внешнего ответа, доступ к конкретному первоисточнику и списание ещё требуют утверждённого запроса. Публичные docs использованы для сверки схемы и тарифа. Один синхронный запрос по рублёвому тарифу оценивается до 0,488 ₽ днём и 0,366 ₽ ночью с НДС. Реальную сумму сверяют по детализации. [Тарификация Yandex Cloud](https://aistudio.yandex.ru/ru/docs/search-api/pricing) · [Схема REST](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search)

Закрытые исследования Softline и утверждённые веса Qwen3-4B в рабочей копии и переданных путях отсутствовали. Статус реального импорта, реального поведения Qwen3-4B и доступа к первоисточникам остаётся открытым. Адриану передан сценарий одного поискового запроса с отдельной процедурой для разрешённой проверки страниц. [Команды и условия приёмки](docs/search_release_handoff.md#одна-одобренная-проверка-kaspersky-endpoint-security)

## Финальный аудит безопасности

| Область | Проверка и граница |
| --- | --- |
| Исходящие данные | Доверенный allowlist товара, доменов и тем. Строитель запроса получает публичное имя, разрешённый домен и фиксированные синонимы. Ключ и ID каталога используются на стороне клиента Yandex Search API. Свободный вопрос, тексты исследований и Метрика в запрос не попадают |
| SSRF, DNS и переходы | Фиксированный API-хост, прямой обход выключен по умолчанию. Для публичных страниц требуется HTTPS на 443, явный допуск страницы и домена текущего запроса. Все ответы DNS проверяются, соединение закрепляется за проверенным числовым адресом, TLS проверяет имя исходного сервера. Переход проверяется заново. Тест подтвердил отказ до DNS для домена, разрешённого глобально, но отсутствующего в запросе |
| Ограничения HTTP и robots.txt | Ограничены время чтения HTTP, страницы, переадресации, размер ответа и пакеты запросов. DNS использует политику системного резолвера. Robots, 429 и Retry-After учитываются до следующей попытки. Недоступная политика и закрытые маршруты оставляют только поисковый сниппет |
| Недоверенное содержимое | Видимый статический текст и ограниченная разметка вместо исходного HTML. Скрытые блоки и типовые инструкции из синтетической страницы отброшены. Метки источника, статусы и ID передаются явно. Устойчивость Qwen3-4B к новым формулировкам инъекций требует отдельной приёмки на реальных весах |
| Секреты и файлы | Нормализованные ссылки с параметрами учётных данных отфильтрованы при разборе и чтении прежнего кеша. Файлы SQLite на POSIX создаются с 0600, старые файлы текущего владельца получают закрытые права. Корпус, снимки и выгрузки пишутся вне Git. На Windows доступ определяется ACL каталога |
| Параллельность и бюджет | SQLite атомарно резервирует попытки до сети, кеш объединяет одновременные обращения одного процесса. Между процессами возможны повторные холодные запросы внутри общего лимита SQLite. Для одного облачного бюджета все процессы должны использовать один согласованный каталог; ограничитель поставщика и отдельный бюджет страниц учитываются дополнительно |
| История и расписание | Снимки отделены от кеша. Пустой успешный ответ не заменяет пригодную базу сравнения. Мониторинг требует явных флагов и внешнего расписания. Экспорт старых снимков читает исходную БД без записи и не меняет её содержимое |

## Интеграция и приёмка

- AI Core получает обычный v1 через существующий ленивый импорт. Снимки мониторинга добавляются через `search_pim_export.py` и штатный `import-history`. Один ключ снимка и поля сохраняет прежние и новые наблюдения, условия, время, происхождение, неизвестные значения и альтернативы. [Контракт PIM](docs/search_release_handoff.md#исторические-снимки-в-общей-pim)
- Qwen получает ограниченный набор сравнений и отдельно компактные изменения между периодами. Сниппет, цитата страницы, локальная запись и гипотеза остаются различимы. Численный вывод используется только при разрешённом статусе и сопоставимых условиях. Бизнес-вывод и проверка ID принадлежат AI Core. [Передача Qwen](docs/search_release_handoff.md#контекст-для-qwen3-4b)
- Интеграцию и допуск к реальному поиску утверждает Адриан. До включения расписания он подтверждает ключ, бюджет и разрешённые домены. Владелец исследований сверяет исходные закрытые XLSX/PPTX. Амир проверяет ссылки и поведение модели на утверждённых весах. [Порядок запуска](docs/search_release_handoff.md)
