# Передача AI Core · уведомления по почте

Фоновый мониторинг ставит письмо в SQLite одновременно с фиксацией завершённого расследования по новому существенному сигналу. Журнал показывает статус почты рядом со ссылкой на расследование. Ручная проверка порога в интерфейсе работает локально. По умолчанию отправка выключена.

## Настройка

Перед обновлением серверной базы v5 остановите пишущие процессы и создайте проверенную независимую копию по действующей процедуре. При заданном `PM_MIGRATION_STATUS_FILE` она нужна для перехода на схему v6. Старые расследования сохраняются в журнале без ретроспективной рассылки. [Резервное копирование и восстановление](docs/backup_and_recovery.md)

Установите переменные в окружении Python-процесса. Шаблон находится в `.env.example`. При локальном запуске Python читает окружение процесса. На сервере используйте закрытый файл окружения, предусмотренный существующим unit. Передавайте SMTP-пароль через согласованное хранилище секретов.

| Переменная | Значение |
| --- | --- |
| `PM_MONITOR_INTERVAL` | Период фоновой проверки и обработки очереди, 60–86400 секунд. Пустое значение отключает расписание. |
| `PM_EMAIL_ENABLED` | `false` по умолчанию. После настройки укажите `true`. |
| `PM_EMAIL_TEST_MODE` | `true` разрешает автоматические письма по синтетическим отчётам. Для рабочих сигналов оператор задаёт `false` после согласования получателей. Синтетические письма всегда помечены как тестовые. |
| `PM_SMTP_HOST` / `PM_SMTP_PORT` | Имя реле и порт. По умолчанию 587 для STARTTLS и 465 для TLS. |
| `PM_SMTP_SECURITY` | `starttls` или `tls`. Оба режима проверяют сертификат и имя SMTP-сервера по системному хранилищу доверия. |
| `PM_SMTP_USERNAME` / `PM_SMTP_PASSWORD` | Задайте оба значения для аутентификации. Оставьте оба пустыми только для доверенного TLS-реле, которое принимает этот процесс без SMTP AUTH. |
| `PM_EMAIL_FROM` / `PM_EMAIL_TO` | Разрешённый отправитель и фиксированный список из 1–5 адресов через запятую. Адресаты передаются в SMTP-конверте. |
| `PM_EMAIL_DAILY_LIMIT` | 1–20 попыток за сутки UTC, по умолчанию 4. Сюда входят повторы и тестовая команда. Одна попытка использует весь настроенный список адресатов. |
| `PM_EMAIL_REPORT_BASE_URL` | Корень защищённого приложения без пути, параметров и учётных данных. Используйте HTTPS за настроенной аутентификацией или loopback через согласованный SSH-туннель, например `http://127.0.0.1:8080/`. Получатель открывает ссылку через тот же туннель. |

До включения откройте корень приложения от имени получателя и проверьте, что страница и `/api/analysis/report` защищены аутентификацией или туннелем. Приложение слушает loopback. Ссылка использует фрагмент `#report=<run_id>` для открытия сохранённого отчёта после загрузки страницы. Права доступа определяет внешний контур.

## Проверочная отправка

1. Настройте разрешённое тестовое реле, отправителя и тестовый ящик в окружении. Оставьте `PM_EMAIL_TEST_MODE=true`.
2. Выполните `python app.py email-test` с тем же `PM_PRIVATE_DIR`, что у сервиса. Временная БД вне репозитория подходит для изолированной проверки.
3. Статус `submitted` означает, что SMTP-сервер принял письмо в обработку. Подтвердите доставку по появлению письма в тестовом ящике.

Команда создаёт одно синтетическое письмо на БД в сутки UTC и включает ссылку на защищённый журнал. Повторный вызов возвращает сохранённый статус или выполняет разрешённый повтор. Для проверки автоматического сценария включите расписание на синтетическом экземпляре и дождитесь нового сигнала. Откройте «Журнал и задачи» и обновите список.

## Содержимое и статусы

Автоматическое письмо содержит название ParadiigmaMGR, факт пересечения порога, значимость, дату сигнала UTC, следующий шаг и ссылку на сохранённый отчёт. Значение индекса берётся только из структурированного синтетического ряда заказов. Для рабочих отчётов письмо содержит краткое описание без закрытых цифр, выдержек, вложений и текста от модели. Тема, получатели и SMTP-настройки заданы сервером.

| Статус | Значение |
| --- | --- |
| `disabled` / `configuration_error` | Отправка выключена, настройки невалидны или изменилось назначение поставленного в очередь письма. |
| `blocked_test_mode` | Тестовый режим пропустил рабочий отчёт. |
| `pending` / `retry` / `sending` | Очередь, ожидание повтора или попытка. |
| `submitted` | Реле ответило `250` на письмо. |
| `failed` | Постоянная ошибка либо исчерпаны попытки. |
| `uncertain` | Соединение прервалось на этапе DATA или процесс завершился во время попытки. Проверьте реле и ящик. Автоматического повтора для этого результата нет. |
| `expired` | Письмо ожидало попытки более суток. |

Временные ошибки дают до двух повторов через 1 и 5 минут с учётом интервала фоновой проверки. Суточная квота удерживает попытки до следующих суток UTC, пока письмо актуально. Смена реле, отправителя, получателей, режима или ссылки закрывает прежние задания с другим назначением. SQLite хранит код результата и отпечаток назначения. Ответы реле и тело письма в журнале отсутствуют.

## Результат проверки

- Прошли 79 тестов Python. Локальный SMTP-сервер принял письма по STARTTLS и TLS. Проверены отказ недоверенного сертификата, ошибка авторизации, недоступное реле, явный отказ `451`, дедупликация, квота, повтор после перезапуска и потеря ответа после передачи DATA.
- Проверены фиксированные получатели, отключённая отправка и отсутствие секретов и выдержек в письме. Миграция v5 → v6 сохраняет прежний журнал без повторной рассылки по старым расследованиям.
- В Chrome открылись сохранённый отчёт по ссылке и статус почты в журнале. Браузерная регрессия прошла.
- Синтетическая приёмка прошла от сигнала до согласования, оценки эффекта, резервной копии и восстановления. После восстановления подтверждены историческое сравнение и новая запись.
- Локальный бэклог сохраняет тег «сгенерирована ИИ-помощником». Согласованная задача экспортируется через `/api/tasks/redmine-export` в существующем Redmine JSON.
- Внешний тестовый ящик и разрешённые реквизиты реле отсутствовали. Доставка во внешний ящик и открытие ссылки через серверный контур остаются операционной проверкой.

Регрессия запускается командой `python -X utf8 -m unittest discover -s tests`. Для SMTP-тестов с временным сертификатом нужен `openssl` в PATH. Для браузерной проверки запускайте `python scripts/qa_browser.py` с Playwright и Chromium или задайте `PM_CHROMIUM` с путём к Chrome.
