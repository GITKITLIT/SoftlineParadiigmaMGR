# Самостоятельная проверка ParadiigmaMGR

Откройте HTTPS-адрес из заявки. Если запрошен вход, используйте учётную запись жюри, полученную отдельным закрытым каналом. Для проверки исходного кода и локального запуска см. [README](README.md).

Сценарий ниже использует демонстрационные данные. Показ в корпоративном контуре и запись на данных задачи проводятся с разрешённым набором. Пример работы с измерением эффекта помечен в интерфейсе как симуляция.

| Шаг | Действие | Что проверить |
| --- | --- | --- |
| 1. Сигнал | Откройте график «Динамика индекса», затем «Журнал и задачи» → «Обновить». Если стенд запущен без фонового задания, используйте «Проверить порог» в блоке агента или кнопку запуска расследования. | В синтетическом ряду индекс заказов падает на 30%. Контроль и окно сравнения видны рядом. На подготовленном стенде фоновый сигнал появляется после первого тика. |
| 2. Расследование | Откройте отчёт по сигналу. Разверните действия агента, доступность источников и гипотезы. | Основной и контрольный ряды, воронка и релиз видны отдельно. Из гипотезы можно перейти к доказательству и прочитать способ проверки. |
| 3. Источники | Откройте конкурентные материалы и релизы. | Поисковый фрагмент и выдержка из первоисточника имеют разное происхождение. Неподключённые источники отображают статус. |
| 4. Чат | Откройте виджет «Открыть чат Qwen». Спросите «Почему снизились заказы? Проверь воронку, интервью, конкурентов и бэклог». Уточните «Как оценить эффект?». | Ответ опирается на отчёт. Уточнение сохраняет контекст. При отключённой Qwen доступен резервный ответ. |
| 5. Согласование | В отчёте или в черновиках чата проверьте название, способ проверки и задайте целевой индекс 110. Подтвердите сохранение. Обновите «Журнал и задачи». | Появится согласованная запись в серверном бэклоге с тегом помощника. Записывайте только синтетические изменения. |
| 6. Redmine | Экспорт согласованной записи доступен через маршрут Backend ниже. Оператор демо может заранее предоставить результат экспорта с этого стенда. | JSON содержит проектную задачу или предложение изменить приоритет существующей. Запись остаётся в локальном бэклоге. |
| 7. План и эффект | Откройте «Как измерить эффект». Для симуляции загрузите `data/effect-demo.json` у согласованной записи. | Фактический режим ждёт четыре полные недели. Пример показывает индекс 120 при цели 110 и пометку симуляции. |
| 8. Память | Откройте «База знаний», режим «Синтетические», выберите ряд и сравните два окна с данными. | Видны происхождение измерений, периоды и расчёт Python. В предварительно наполненном сценарии «Демо · история заказов» сравните 08.05.2024 и 08.05.2025, задав для каждого окна одинаковые начало и конец. |

Для проверки экспорта из консоли браузера на уже открытом стенде используйте идентификатор согласованной задачи из ответа `POST /api/tasks`. Этот вызов выполняет только чтение экспорта и использует текущую сессию:

```javascript
const taskId = "ID_СОГЛАСОВАННОЙ_ЗАДАЧИ";
const response = await fetch("/api/tasks/redmine-export", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({task_id: taskId})
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
console.log(await response.json());
```

При нагрузке дождитесь конца расследования и обновите журнал один раз. Если статус модели сообщает об ограничении, проверьте численные наблюдения и ссылки в резервном отчёте. Проверка доставки email, внешних источников и восстановления выполняется оператором.
