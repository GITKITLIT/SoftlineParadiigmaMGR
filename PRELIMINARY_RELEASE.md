## Быстрый переход к финальной сборке

1. После получения передачи заново выполнить `git fetch --no-tags origin`. Зафиксировать полный SHA предварительной сборки и утверждённые SHA каждого нового handoff. Создать отдельный финальный кандидат от предварительного SHA. Записать хэш GGUF, режим Qwen, схему SQLite и версию, доступную жюри.
2. Принять от Максима установленный релиз, сетевую схему, HTTPS и вход жюри, проверку резервной копии и цены. От Амира нужны версия runtime, итоговый профиль, повторные измерения Sandy Bridge, результат проверки качества и поддерживаемая параллельность. Зафиксировать подтверждение Search на целевом стенде и отдельно выбранный набор демонстрационных данных.
3. Проверить каждый новый diff и dry run. При наличии пересечений в прокси, systemd и backup проверить вместе с миграцией и ролями из [интеграционного отчёта](INTEGRATION_REPORT.md). Переносить утверждённые изменения по одному, сохраняя независимую историю. При затрагивании схемы сначала проверить восстановление на копии.
4. Провести целевую приёмку ниже. В [чек-лист сдачи](SUBMISSION_CHECKLIST.md) внести итоговые SHA, URL, запись и ссылку на официальный Excel. Проверить всё как гость. Капитан выполняет отправку через кабинет.

### Sandy Bridge

По промежуточной диагностике второй модельный шаг занял **44,438 с** при штатном лимите **26 с**. Из них **42,582 с** пришлись на обработку входа. Весь диагностический запрос занял **51,828 с**. Тестовый клиент использовал увеличенные пределы для измерения. Эти значения не входят в конфигурацию предварительной сборки. Для записи используйте запасное сравнение Python из бизнес-сценария, если живой ответ не помещается в эпизод. [Отчёт Qwen, промежуточная диагностика](https://github.com/GITKITLIT/SoftlineParadiigmaMGR/blob/3ba13eba2f78b12b51a044e3df54da87748629f5/handoff/qwen-final/QWEN_LINUX_ACCEPTANCE.md)

## Откат

- Если новый handoff не проходит проверку, остановить продвижение кандидата. Для продолжения создать новое рабочее дерево от последнего прошедшего SHA либо сделать revert изолированного изменения по результатам ревью. После публикации историю веток не переписывать.
- Перед переключением стенда Deployment сохраняет предыдущий SHA, эффективную конфигурацию и пару «версия схемы + проверенный снимок». При ошибке остановить записи, восстановить совместимый код и состояние в порядке из [runbook развёртывания](docs/combined_release_deployment.md) и [плана восстановления](docs/disaster_recovery.md). Подтвердить целостность, вход жюри, доступ к прежнему отчёту, новую запись и очередь писем.
- При сбое только модели вернуть предыдущий утверждённый профиль и адрес API по [инструкции Qwen](docs/qwen_runtime.md). Затем проверить здоровье модели, историю и fallback. Откат целевого стенда выполняет Deployment в согласованное окно. Предварительная сборка никаких изменений на стенде не выполняла.
